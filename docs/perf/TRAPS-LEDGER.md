# Performance audit — traps ledger

Things that misled, broke, or measured worse. Read before doing performance work on Headroom.

| # | Trap | What happened | How to avoid it |
|---|---|---|---|
| 1 | Device animations were off | The Pixel 7 Pro had `animator_duration_scale`, `transition_animation_scale` and `window_animation_scale` all at `0` (left by UI-test tooling). Compose then finishes every animation in one frame and endless ones never start: the first idle and fling measurements looked perfect and meant nothing. | Check `adb shell settings get global animator_duration_scale` before measuring; set all three to `1`, and put back the user's values afterwards (this audit restores `0`). |
| 2 | Old trace_processor | The prebuilt `trace_processor_shell` v54 cached by Perfetto's Python tooling refuses Android 17 traces ("Field message_queue is re-introduced with different type"). | Use v58+ from `https://get.perfetto.dev/trace_processor`. |
| 3 | Back on a top-level tab leaves the app | A scripted `back` on the Resets tab closed Headroom, and the next scripted taps landed in the launcher and opened other apps. | Leave tabs by tapping Overview; scenarios must end where they started (see `scripts/perf/suite.sh`). |
| 4 | Real install on the test phone | The phone has the user's release-signed Headroom with real accounts; a debug or differently signed build cannot be installed over it without uninstalling (data loss). | The `benchmark` build type installs next to it as `dev.sebastiano.headroom.benchmark`. Never run `release-smoke-test.sh` (it uninstalls) against this phone. |
| 5 | gfxinfo frame percentiles at 120 Hz | `dumpsys gfxinfo` percentiles are 1 ms buckets of the whole pipeline (p50 ≈ 10 ms on a smooth fling), so they cannot be compared with the 8.33 ms budget. | Use FrameTimeline jank types and main/render-thread work per frame (`scripts/perf/ftl.py`). |
| 6 | atc lease lapsed silently | `atc claim` without `--ttl` gives a 10-minute lease. Mine lapsed while I was reading code, atc handed the phone to another agent (Clockblocker perf work), and both of us drove it at once: its app sat in the foreground during my "idle" trace, and my animation-scale changes ruined its run. | Claim with `--ttl` that covers the whole session (or `atc renew`), check `atc status --json` before every device run, and check `dumpsys window \| grep mCurrentFocus` shows the app under test. |
| 7 | Orphaned lease after an agent left | The other agent's lease kept renewing under the shared `jetski` parent process, so atc never saw it as dead. | With the owner's go-ahead, `ATC_SESSION=<their session> atc free <lease id>`. |
| 8 | App sections missing after a reinstall | After `adb install -r`, the `START` broadcast was accepted but the running process recorded nothing: the pulled in-process trace was 261 bytes. | After reinstalling, send `START`, then force-stop and relaunch the app before tracing. Check that `app/*.perfetto-trace` is hundreds of KB. |
| 9 | Haze blur redraws at the frame rate of whatever moves under it | With the overview scrolled, the status-bar blur is on. Idle frames then jank (8–11 per 5 s) because every frame re-blurs the strip under the status bar. | Measure the idle overview both at the top and scrolled. |
| 10 | Commits are signed through 1Password | `git commit` fails with "1Password: agent returned an error" while 1Password is locked or waiting for approval, which looks like a silent no-op in a background shell. | Check `git log` after committing. Leave the work staged and ask the owner to unlock 1Password; do not turn signing off. |
| 11 | Worst frame is noisy | For unchanged screen openings, the median over 5 runs of each run's worst frame moved by ±10 ms between sessions (tabs 63 → 75 ms, all_resets 72 → 63 ms in two runs of code that does not affect them). | Judge screen openings with app jank counts and the A/B procedure in one session, or use more runs. Do not read a 10 ms change in `uiMax` as a result. |
| 12 | Frame counts move with idle redraws | After W2, `detail_open` and `detail_scroll` show far fewer frames (403 → 281, 384 → 117) because their idle seconds now draw at 30 fps. Per-frame percentiles shift for the same reason. | Compare jank counts and frame times, not frame counts, across a change to idle drawing. |
| 13 | ktfmt's root `ktfmtFormat` races | Running `ktfmtFormat` across all modules failed twice with "Could not read path …/build/tmp/ktfmtFormat…/….txt" from another module's `ktfmtFormatScripts`. | Format the modules you touched (`:core:designsystem:ktfmtFormat`), or retry. |
